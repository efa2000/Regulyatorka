# Что создать в личном кабинете Cloud.ru, чтобы Claude мог подключаться

Консоль: https://console.cloud.ru. Всё ниже — по официальной документации
(https://cloud.ru/docs/console_api/ug/topics/quickstart и соседние статьи).

## 1. Проект и его ID

Организация и проект создаются при регистрации. ID проекта нужен в каждом запросе.
Скопировать: в верхней панели раскрыть список проектов → в строке проекта «Скопировать ID проекта».
Или: Администрирование → Каталоги и проекты.

## 2. Сервисный аккаунт

Пользователи → Сервисные аккаунты → «Создать аккаунт»:

- Название: `claude-code`, описание по вкусу.
- Уровень: **Проект** (роли только внутри одного проекта; после создания уровень и проект не меняются).
- Проект: наш.
- Роль в проекте: **Администратор проекта** (`platform.project.admin`) — так рекомендует квикстарт.
  Он включает «Администратор пользователей» и «Пользователь проекта», то есть подключение сервисов и
  работу с ресурсами. Для только-чтения подошёл бы «Наблюдатель проекта» (`platform.project.viewer`),
  для работы без управления пользователями — «Пользователь проекта» (`platform.project.user`).
- «Роли на организацию» оставить пустыми.

Дождаться статуса «Активен».

## 3. Ключ доступа

Открыть созданный аккаунт → блок «Учётные данные доступа» → вкладка **Ключи доступа** → «Создать ключ»:

- описание: `claude-code на машине efa`;
- срок жизни: ограниченный (30–90 дней; бессрочные ключи дока называет менее безопасными).

Появятся **Key ID** (логин) и **Key Secret** (пароль). Key Secret показывается один раз — сохранить сразу.
У одного аккаунта может быть до 20 ключей, так что ротация без простоя.

Не путать с «API-ключами» (вкладка рядом): это другой механизм (`Authorization: Api-Key`), он нам не нужен.

## 4. Положить учётные данные на машину

Не в чат и не в репозиторий, а в файл (можно через `!` прямо в сессии Claude Code):

```bash
mkdir -p ~/.config/cloudru && chmod 700 ~/.config/cloudru
cat > ~/.config/cloudru/credentials <<'EOF2'
CLOUDRU_KEY_ID=<Key ID>
CLOUDRU_KEY_SECRET=<Key Secret>
CLOUDRU_PROJECT_ID=<ID проекта>
EOF2
chmod 600 ~/.config/cloudru/credentials
```

Проверка: `.claude/skills/cloudru/scripts/cloudru-api.sh whoami` должна вернуть JSON с проектом.

## 5. По необходимости позже

- **Object Storage**: тот же ключ доступа, плюс tenant_id из Хранение данных → Object Storage →
  Параметры работы с API.
- **Баланс**: платные сервисы (ВМ, PostgreSQL) требуют положительного баланса; привязка карты даёт бонусы,
  free tier покрывает Object Storage и Container Apps.
- **Ротация**: новый ключ создать до истечения старого, заменить файл, старый удалить
  (Ключи доступа → удалить).

## Роли, справочно

Организация: `platform.customer.admin` (всё), `quota-admin`, `support-admin`, `expense-admin`, `viewer`.
Проект: `platform.project.admin` ⊃ `iam-admin` + `user`; `service-user`, `support-user`, `viewer`.
Сервисный аккаунт как объект: `iam.serviceaccount.viewer` / `user` / `admin` / `impersonator`.
Наследование сверху вниз: организация → проект → сервисы. Подробно:
https://cloud.ru/docs/administration/ug/topics/concepts__roles.
