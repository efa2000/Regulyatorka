# Контракт: агрегатор ↔ сервер семейства

Решение от 24.10.2026. Как агрегатор разговаривает с сервером семейства. Роли сторон — `федерация.md`,
модель документа, норматива и связи — `библиотека.md`, единица ответа — `поиск.md`.

- **Транспорт.** JSON поверх HTTP, UTF-8. Одна схема OpenAPI на все семейства, живёт в общей библиотеке; сервер
  семейства собирается из неё, агрегатор по ней валидирует. MCP — только у агрегатора для клиентов, семейству не нужен.
- **Доверие.** Сервер внутренний, доверяет агрегатору, клиентских ключей нет. Таймаут на семейство держит агрегатор.
- **Версии.** `contract_version` отдаётся в методе возможностей. Контракт меняется только добавлением полей:
  смысл и тип существующего поля не меняются, поля не удаляются. Неизвестные поля обе стороны игнорируют.
- **Даты** — `YYYY-MM-DD`. «Сегодня» — по московскому времени.

## Идентификаторы

- **`doc_id` уникален во всей федерации**: адресные вызовы маршрутизируются через каталог по идентификатору
  документа, а одно обозначение бывает у разных семейств (санитарный и строительный СП). Вид: `<код семейства>:<обозначение>`,
  обозначение — латиницей и цифрами в нижнем регистре: `san:sp-2.4.3648-20`, `str:sp-118.13330.2022`.
- **`chunk_id`** — непрозрачный ключ фрагмента. Агрегатор его не разбирает и передаёт обратно в `get_clause` тому же
  семейству. После смены `base_version` может устареть — тогда ошибка `stale_chunk` (ниже).
- **`address`** — строка для человека и цитаты; разбор на части — внутри семейства.

Коды семейств — **предложение, принятого списка нет**:

| Семейство | Код |
|---|---|
| санитарные правила | `san` |
| федеральные законы | `fz` |
| акты Правительства | `pp` |
| указы | `uk` |
| строительные нормы | `str` |
| стандарты | `gost` |
| пожарная безопасность | `mchs` |
| охрана труда | `ot` |
| акты Банка России | `cbr` |
| техрегламенты ЕАЭС | `eaeu` |

## Общее для всех ответов

Успешный ответ — конверт:

| Поле | Тип | Что |
|---|---|---|
| `family` | string | код семейства |
| `base_version` | string | версия базы, например `2026.10` |
| `base_date` | date | дата актуальности базы |
| `as_of` | date | дата среза: параметр `as_of` запроса или сегодня |
| `simplified` | [string] | пометки упрощённого режима, пусто — полный режим |
| `result` | object | ответ метода |

Пометки `simplified`: `rerank_unavailable` (реранк запрошен, модель недоступна — исходный порядок),
`vector_unavailable` (поиск только по словам), `norm_index_partial` (индекс норм собран не по всем таблицам).
Пометка «из скана» — на фрагменте, не в конверте.

Ошибка — HTTP-код и тело `{"error": {"code", "message", "suggestions"}}`. `suggestions` — список
`{doc_id, address, title, reason}`, где `reason`: `replaced_by`, `similar_designation`, `nearest_address`, `other_family`.

| Код | HTTP | Когда |
|---|---|---|
| `bad_request` | 400 | нарушена схема, недопустимый ключ или значение `filters` |
| `doc_not_found` | 404 | нет такого документа; в `suggestions` — похожие обозначения и замены |
| `clause_not_found` | 404 | документ есть, адреса нет; в `suggestions` — ближайшие адреса |
| `locator_unparsed` | 422 | строку-локатор не удалось разобрать по схеме адресов семейства |
| `no_edition_on_date` | 404 | на `as_of` документ или фрагмент ещё не действовал или уже исключён; в `suggestions` — ближайшая редакция |
| `stale_chunk` | 410 | `chunk_id` из прошлой `base_version`; в `suggestions` — тот же адрес в текущей |
| `no_norm_index` | 501 | у семейства нет индекса норм |
| `unavailable` | 503 | база перезагружается или зависимость недоступна |
| `internal` | 500 | прочее |

## Фрагмент

Единица результата всех поисковых и адресных методов (виды и комплектность — `поиск.md`).

| Поле | Тип | Что |
|---|---|---|
| `chunk_id` | string | непрозрачный ключ |
| `doc_id` | string | документ |
| `doc_short` | string | обозначение («СП 2.4.2.4283-26») |
| `doc_title` | string | полное название |
| `doc_status` | enum | статус документа на дату среза: `active`, `repealed`, `expired`, `not_in_force` |
| `kind` | enum | `clause` (пункт, подпункт, абзац; у законов — статья, часть, пункт), `table_row`, `table`, `document_card`, `form`, `term` |
| `address` | string | подпись для человека («СанПиН 1.2.3685-21, табл. 5.54, строка 15») |
| `path` | [{`label`, `title`}] | путь от документа до фрагмента с названиями разделов и статей — подпись перед фрагментом |
| `url` | string | страница для человека с документом в этом месте; хост — публичный шлюз, который по префиксу `doc_id` проксирует запрос на сервер семейства (решение от 24.10.2026); напрямую сервер семейства снаружи недоступен |
| `source_url` | string | официальное опубликование |
| `text` | string | текст дословно |
| `status` | enum | статус формулировки на дату среза, те же значения, что у `doc_status` |
| `edition` | object | `valid_from`, `valid_to` (null — по сей день), `amended_by` (`doc_id`, `address`, подпись), `consolidation`: `official` или `ours` |
| `scan` | object \| null | текст из скана: `confidence` — уверенность распознавания, 0…1 |
| `score` | number | локальная оценка семейства; между семействами не сравнивается; в адресных методах отсутствует |
| `table` | object | только у `table_row` и `table`, ниже |
| `links` | [link] | связи фрагмента, ниже |
| `base_version` | string | версия базы, из которой фрагмент |
| `family_attrs` | object | семейные атрибуты фрагмента, ключи — как в `filters` из возможностей |

**`table`** — строка таблицы по модели норматива (`библиотека.md`), отдаётся в комплекте:

| Поле | Что |
|---|---|
| `number`, `title` | номер и полное название таблицы; номер может повторяться в документе — различает `address` |
| `header` | шапка столбцов с единицами |
| `group` | группа строк (раздел внутри таблицы), путь, если вложенная |
| `row` | номер и подпись строки |
| `values` | величины строки: `indicator` (показатель), `raw` (значение дословно), `min`, `max` (разобранные границы, null — нет), `unit`, `qualifier` (`at_least`, `at_most`, `range`, `exact`), `period`, `conditions` (подстрока, столбец-условие), `footnotes` (метки) |
| `footnotes` | сноски: `mark`, `text`; `text` = null, если в публикации есть только метка |
| `notes` | пункты-примечания вне таблицы, меняющие норму: `address`, `text` |

У `kind: table` вместо `row` и `values` — `rows`: все строки в том же виде.

**`link`** — связь (сетка из `источники.md`, раздел о связях). Отсылка — полноценный ответ (`библиотека.md`).

| Поле | Что |
|---|---|
| `scope` | цель: `internal`, `family`, `other` |
| `form` | `full` (полные реквизиты), `short` (краткое обозначение), `generic` (родовая: «устанавливается Правительством»), `alias` (внутреннее сокращение, «далее —») |
| `nature` | `dependency` или `mention` |
| `text` | ссылка как в документе |
| `target` | `doc_id`, `address`, `doc_short`; null у неразрешённой |
| `resolved` | разрешена через каталог или нет |

## Фильтры

Общие для поиска и запроса числа:

| Параметр | Тип | По умолчанию |
|---|---|---|
| `domain` | [string] | все области; теги области на документе или разделе |
| `doc_ids` | [string] | все документы семейства |
| `as_of` | date | сегодня |
| `status` | [enum] | `["active"]` — действующие на `as_of` |
| `limit` | int | не зафиксировано до прототипа |
| `filters` | object | `{}` |

`filters` — семейные атрибуты (среда, адресат, тип объекта, класс Ф, группа продукции и т. п.). Допустимые ключи и
их типы семейство объявляет в методе возможностей. Агрегатор валидирует по объявлению, неизвестные ключи отбрасывает
и пишет об этом в ответ клиенту; семейству приходят только объявленные, остальное — `bad_request`.

## Методы

### `POST /search` — поиск

Запрос: `query` (string, обязателен) + общие фильтры + `rerank` (bool, по умолчанию `false`).

Семейство отдаёт верхушку кандидатов **без реранка**: объединение от всех семейств переранжирует агрегатор общим
реранкером. `rerank: true` включает реранк на стороне семейства — нужен для собственного эталона; поддержка
объявляется в возможностях. Точные совпадения по адресу — первыми.

Ответ: `result.items` — [фрагмент].

Пример элемента:

```json
{
  "chunk_id": "…",
  "doc_id": "san:sp-2.4.2.4283-26",
  "doc_short": "СП 2.4.2.4283-26",
  "doc_title": "…",
  "doc_status": "active",
  "kind": "clause",
  "address": "СП 2.4.2.4283-26, подпункт 5 пункта 20",
  "path": [
    {"label": "СП 2.4.2.4283-26", "title": "…"},
    {"label": "раздел …", "title": "…"},
    {"label": "пункт 20", "title": null},
    {"label": "подпункт 5", "title": null}
  ],
  "url": "https://<шлюз>/doc/san:sp-2.4.2.4283-26/…",
  "source_url": "…",
  "text": "5) … не менее 300 люкс …",
  "status": "active",
  "edition": {"valid_from": "2026-09-01", "valid_to": null, "amended_by": null, "consolidation": "ours"},
  "scan": {"confidence": 0.97},
  "score": 0.91,
  "links": [],
  "base_version": "2026.10",
  "family_attrs": {}
}
```

### `POST /lookup_norm` — запрос числа

Запрос: `indicator` (string, показатель, обязателен), `object` (string, объект), `conditions` ([string], условия
словами) + общие фильтры. Ищет по записям индекса норм на величину.

Ответ: `result.items` — [фрагмент `kind: table_row`] со строкой в комплекте. Нет индекса — `no_norm_index`.

Пример элемента (поля, общие с поиском, сокращены):

  "text": "…",

### `POST /get_clause` — фрагмент по адресу

Запрос — один из двух входов:
- `chunk_id` из результата;
- `doc_id` + `locator` — строка адреса как у человека: «п. 2.4.6», «ч. 1 ст. 24», «табл. 5.54», «пункт 28 приложения 6».
  Разбор локатора — внутри семейства, схема адресов — его свойство.

Плюс `as_of` (date, сегодня) и `history` (bool, `false`).

Ответ `result`:

| Поле | Что |
|---|---|
| `fragment` | фрагмент целиком: пункт со всеми подпунктами, таблица со всеми строками и сносками |
| `parent` | родитель: `chunk_id`, `address`, `path`, `text` |
| `neighbors` | `prev`, `next`: `chunk_id`, `address` |
| `links` | связи фрагмента |
| `editions` | только при `history: true` — все редакции фрагмента: `edition`, `status`, `text` (или `table`) |

Отдельного метода истории нет: «что изменилось» и «что действовало на дату» — `get_clause` с `history` или `as_of`.

### `GET /documents` — карточки документов

Семейство — источник истины по своим документам; каталог агрегатора синхронизируется при каждой новой `base_version`.

- `GET /documents/{doc_id}` — одна карточка.
- `GET /documents?since_version=<base_version>` — карточки, изменённые после этой версии; без параметра — все.
  В `result.removed` — `doc_id`, исчезнувшие из семейства.

Карточка: `doc_id`, `doc_short`, `doc_title`, `doc_type`, `publisher`, `date`, `number`, `aliases` (обозначения для
разрешения: с годом и без, жаргон), `status`, `status_date`, `valid_from`, `valid_to`, `replaces`, `replaced_by`
(обозначение и `doc_id`, если разрешено), `editions` (`valid_from`, `amended_by`, `consolidation`), `domain`,
`has_text` (карточка без текста — ГОСТ), `url`, `source_url`, `changed_in` (`base_version` последнего изменения).

### `GET /capabilities` — возможности

| Поле | Что |
|---|---|
| `family`, `family_title` | код и название |
| `contract_version` | версия контракта, которую реализует сервер |
| `base_version`, `base_date` | версия и дата актуальности базы |
| `doc_types` | типы документов семейства |
| `norm_index` | есть ли индекс норм |
| `rerank` | поддерживается ли `rerank: true` |
| `filters` | допустимые ключи: `{ключ: {type, values?, title}}`, `type` — `enum`, `string`, `number`, `range`, `bool` |
| `locators` | поддерживаемые виды локаторов: `clause`, `subclause`, `paragraph`, `article`, `part`, `table`, `table_row`, `appendix`, `footnote`, `term` |

### `GET /health` — здоровье

`200 {"status": "ok", "base_version": "…"}`; база не загружена — `503 unavailable`.

## Чего контракт не фиксирует

Оставлено до прототипа: таксономия тегов области, размер верхушки кандидатов и `limit` по умолчанию, принятый
список кодов семейств, домен шлюза в `url`.

Возможное расширение, пока не нужно: фильтр по виду фрагмента (`kind`) в поиске.
