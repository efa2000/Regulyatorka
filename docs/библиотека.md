# Общая библиотека: как работаем с документами и ищем

Решение от 24.10.2026 по итогам разбора вопросов (`поиск.md`, `вопросы/`). Здесь — что делаем одинаково для всех
семейств и где начинается семейное. Принцип федерации: библиотека общая, сервер у каждого семейства свой (`федерация.md`).

## Работа с документом

1. **Текст только из официального источника** (`источники.md`). Для actual и ИПС источник текстовый, сверяем с ним.
   Для сканов (cbr.ru, protect.gost.ru, свежие публикации) — распознавание со сверкой по изображению страницы,
   у фрагмента пометка «из скана» с уверенностью распознавания.
2. **Дословно.** Цифры, единицы, опечатки — как в оригинале, без толкований. Служебные записи (пометки о редакции,
   источники публикации и регистрации, шапки) сохраняем, но размечаем как служебные.
3. **Канонический формат — структурированное дерево (JSON) с устойчивыми идентификаторами абзацев**, по одному на
   каждую редакцию. Markdown, фрагменты для поиска и страница для человека выводятся из него. Markdown как основное
   хранение не вмещает объединённые ячейки, сноски на отдельном значении, две таблицы с одним номером, абзацы без
   номера с исключениями, вставленные пункты (5¹ и 51), ненумерованные части статей.
4. **Редакции — история на уровне пункта**, не одна действующая. У формулировки: с какой даты, каким актом, отложенное
   применение, подписанные и не вступившие изменения. Для законов, указов и постановлений Правительства консолидация
   официальная с actual; для остальных семейств собираем сами из инструкций «изложить в редакции» с признаком
   «собрано нами» и сверкой.
5. **Текст храним для всех редакций и статусов.** Статусы: действует / отменён / истёк срок без замены / не вступил.
   «На дату», «что изменилось», таблица соответствия пунктов при замене и ссылки на конкретный год редакции
   требуют старого текста. Карточка без текста — только там, где текста законно нет (ГОСТ). Фильтр «только
   действующие» — в поиске по умолчанию, не в хранении.
6. **Нормативы из таблиц — в индекс норм**, производный от текста. Единица — строка таблицы: внутри несколько величин,
   каждая со своим показателем, единицей, квалификатором (не менее / не более / диапазон), периодом и сносками. К строке
   привязаны шапка, группа строк, полное название таблицы и пункты-примечания вне таблицы, меняющие норму. Запись
   на величину — для поиска «сколько»; отдаём строку в комплекте. Сначала собирает программа, потом сверка с источником.
7. **Связи извлекаем и разрешаем через каталог** (`источники.md`, раздел о связях). Отсылка — полноценный ответ
   («определяет изготовитель», «устанавливается Правительством», «по СП 309»), не «нормы нет».

## Хранение

- Неизменяемые артефакты — в S3 (Cloud.ru): исходники как скачаны, результат распознавания, дерево каждой редакции.
  Один бакет на все семейства, конвейер воспроизводим.
- Индекс поиска и каталог — PostgreSQL (управляемый в Cloud.ru): полнотекст с русской морфологией и векторы в одной базе. Отдельный векторный движок не заводим, пока семейств мало.

## Нарезка на фрагменты

- Обычная единица — пункт с подпунктами и примечаниями; длинный пункт режется по подпунктам или абзацам; короткие не
  склеиваются. Адрес внутри фрагмента разрешается до абзаца.
- Таблица — фрагмент; большая делится на группы строк с повтором названия и шапки.
- Сноски — к фрагменту, который на них ссылается.
- Ещё три типа фрагмента: карточка документа, приложение-форма (обязательная или рекомендуемый образец), статья термина.
- Перед фрагментом — подпись: документ, путь с названиями разделов и статей, адрес.

## Поиск

1. **Разбор вопроса:** адреса («пункт 28 приложения 6», «ч. 1 ст. 24»); обозначения с нормализацией (без года →
   действующая редакция, ГОСТ → ГОСТ Р, «683» без суффикса неоднозначен, жаргон); дата («на 01.01.2025»); атрибуты объекта.
2. **Одновременно:** по смыслу, по словам с русской морфологией, по точному адресу, **и атрибутные фильтры** — среда,
   адресат, тип объекта, группа продукции; параметры объекта (площадь, этажность, класс) — фильтр по диапазонам в таблицах.
3. **Слияние:** точные совпадения по адресу первыми.
4. **Фильтры:** по умолчанию действующие на сегодня; дата из вопроса меняет срез; область — тег на документе.
5. **Переранжирование** около 40 кандидатов отдельной моделью; при её недоступности — исходный порядок и пометка «упрощённо».

Модели эмбеддинга и переранжирования — из Cloud.ru (Foundation Models), одни на все семейства; конкретные подберём на прототипе поиска, когда будет на чём мерить.
6. **Дополнение:** адрес, ссылка на место в документе, сведения о документе, статус и редакция пункта, шапка для строки,
   родительский пункт для подпункта, разрешённые отсылки и делегирование.

Отдельный запрос для чисел берёт запись из индекса норм и возвращает строку таблицы в комплекте.

## Граница: общее и семейное

| Общее (библиотека) | Семейное (сервер семейства) |
|---|---|
| модель документа, схема адресов, устойчивые идентификаторы | распознаватели структуры: схемы нумерации, статья/часть, вставки, римские разделы |
| модель редакций и статусов на уровне пункта | консолидация своя или с портала; разбор инструкций изменений |
| модель норматива и индекс норм | какие таблицы нормативные и что значат столбцы |
| правила нарезки, все типы фрагментов | — |
| конвейер поиска, упрощённый режим, запрос чисел | словари и экстракторы атрибутов: среда и CAS, профессии, класс Ф, группа продукции и ТН ВЭД, адресат-организация, ОКС |
| каталог: документы, статусы, замены, редакции, разрешение обозначений | особые статусы: реестр требований Минстроя, этап Минюста, территория у ГОСТ |
| модель связи | извлечение связей: сноски, библиография, «Нормативные ссылки», «далее —», цепочки замен |
| адаптеры actual и ИПС, распознавание сканов | адаптеры к остальным источникам, теги области для смешанных семейств |
| эталон и раннер | вопросы эталона по семейству |

Эталонный набор вопросов с адресами ответов — обязателен; любое изменение нарезки, моделей или правил выкатывается
после прогона и сравнения с прошлым результатом. Формат записи: вопрос, семейство, ожидаемые адреса, дата среза.
Раннер считает попадание ожидаемого адреса в первые несколько результатов и сравнивает с прошлым прогоном.
Заготовка — `вопросы/`.

## Порядок работ

Библиотеке нужны минимум два семейства, иначе общее не отличить от случайного. Начинаем парой: **санитарные
правила** (ядро продукта, сложные таблицы, своя консолидация) и **акты Правительства с законами через actual**
(текстовый источник с готовой консолидацией — даёт модель редакций и адаптер actual). Вместе закрывают типовой
стык «СанПиН + 52-ФЗ + ПП». Отложено до прототипа: выбор моделей, таксономия тегов области, размер фрагментов.
