# Семейство «техрегламенты ЕАЭС»: кто спрашивает и что считать ответом

Что смотрел (ВМ `regulyatorka-fetch`, `~/src/other/`):
- исходный текст ТР ТС 021/2011 (`eec_TR-TS-021-2011.txt`, PDF из Word, редакция 2011 г. без изменений);
- изменения по Решению Совета ЕЭК № 115 (`eaeu_115_att/Изменения в ТР.docx.txt`);
- карточку ТР 021 на eec.eaeunion.org (`eec_TR021.html`), список ТР (`eec_TRVsily.html`), XML API (`eaeu_data.xsd`, `eaeu_api_*.xml`).

«Проверено» ниже значит, что текст сверен с исходной редакцией 2011 г. и с решением 115. Карточка ТР называет ещё четыре изменяющих решения Совета ЕЭК: № 61 от 14.07.2021, № 173 от 25.11.2022, № 70 от 23.06.2023, № 35 от 22.04.2024. Их текстов у меня не было, так что действующую редакцию по ним я не сверял.

Мелочи источника, которые всплыли по ходу:
- `eaeu_SovetEEK_115_2019_a.docx.txt` — это **армянская** версия приложения. Русская лежит в `eaeu_115_att/`.
- `eaeu_SovetEEK_115_2019.txt` пустой (11 байт): у PDF нет текстового слоя.
- В DOCX решения 115 надстрочные номера потеряны: «позиция 61», «371», «2141» в приложении 7 на деле означают 6¹, 37¹, 214¹. Это вставки между существующими позициями, а не позиция № 61.
- В PDF-тексте ТР степени разъехались по строкам: «1х10 3» — это 1×10³. Номера страниц («54», «142») попадают внутрь таблиц.

Для агрегатора: вопрос ко ТР почти никогда не закрывается одним семейством.
- Методы испытаний → **стандарты**.
- Родовые отсылки «законодательство государства-члена» → **федеральные законы, акты Правительства, санитарные правила**.
- Для продукции вне ТР — ЕСТ (Решение КТС № 299) и Единый перечень товаров, подлежащих санэпиднадзору. Это решения КТС/ЕЭК, то есть то же семейство.

## 3. Что должен уметь поиск

**Входы.**
- **По виду продукции.** Бытовое название («творожок», «энергетик», «пюре для малышей», «тестомес») → термин ТР («пищевая продукция для детского питания для детей раннего возраста», «тонизирующие напитки», «машины») → группа продукции в строках таблиц (колонка «Примечания» приложений 2–3) → ТН ВЭД из перечней продукции. Синонимия и иерархия групп — отдельный словарь семейства, его строим из определений статьи 4 и названий разделов приложений.
- **По показателю.** Микробиология (КМАФАнМ, БГКП, сальмонеллы, L. monocytogenes), токсичные элементы, микотоксины, пестициды, антибиотики, радионуклиды. Норма = показатель × группа продукции × условия (масса навески, вид обработки, срок годности). Это `lookup_norm` с conditions, как в санитарном семействе, но с осью «группа продукции» вместо «вид организации».
- **По процедуре.** Декларирование, схемы, госрегистрация, ВСЭ, регистрация объектов, заявитель — статьи глав 4–5.
- **По обозначению.** «ТР ТС 021», «021/2011», «ТР ЕАЭС 040», «технический регламент о пищевой продукции», «решение 880», «решение 115» — детерминированно через каталог.
- **По редакции на дату.** Изменения приходят отдельными решениями. У каждой правки — дата вступления (часто «через 180 дней после опубликования», то есть дату надо вычислить) и отдельный акт с переходными положениями (Решение Коллегии № 69 к решению 115). Поиск должен отдавать текущую редакцию, редакцию на дату и историю строки или пункта: «было < 0,01 → стало < 0,0003 с 11.07.2020».
- **По связям.**
  - ТР → перечни стандартов (решение Коллегии + цепочка изменений) → строка → ГОСТ (семейство «стандарты»).
  - ТР 021 → ТР «на отдельные виды» (вертикальные) и горизонтальные (022, 005, 029).
  - ТР → национальное законодательство по родовым ссылкам.
  - ТР → документы применения: рекомендации ЕЭК, «актуальные вопросы» на eec.eaeunion.org.

**Что мешает.**
- **Родовые внешние ссылки.** «ТР, устанавливающий требования к маркировке», «соответствующие ТР», «законодательство государства-члена». Номеров нет ни у ТР, ни у ГОСТ, поэтому граф связей строится не из текста: карточка ТР на eec.eaeunion.org, перечни стандартов, ручная таблица «родовая ссылка → акт РФ».
- **Большие многостраничные таблицы.** Приложения 2–3 — около 3800 строк текста. Колонки разъезжаются, степени отрываются («1х10 3»), номера страниц попадают внутрь таблиц, одна группа продукции рвётся на две страницы. Чанк «по странице» бесполезен: единица — строка «показатель — уровень — группа продукции» с заголовками раздела и таблицы.
- **Консолидация из инструкций.** «Цифру «, 5» исключить», «позицию дополнить строкой», «разделы 1.10 и 1.13 исключить». Надстрочные номера вставок теряются в DOCX (6¹ превращается в «61»). Часть изменяющих решений — PDF без текста. Консолидацию надо сверять, у элемента — флаг «редакция собрана нами».
- **Переходные положения.** Старую и новую норму в переходный период можно применять параллельно, и декларации по старой редакции действуют. Ответ «норма — X» без этого неполон.
- **Несколько ТР на один товар.** Пищевка: горизонтальный 021 + вертикальный + 022 + 005 + 029. Машины: 010 + 004 + 020 + 037. Вертикальный ТР может уточнять, но не изменять 021 (часть 3 статьи 1), а схемы и сроки деклараций могут быть «иными» (части 3, 5, 10 статьи 23). Поиск должен отдавать набор применимых ТР, а не одну лучшую статью.
- **Смещённые нормы.** Молочка ищется в 021, а нормативы в 033. Нужна явная связь «раздел отсутствует / см. ТР 033».
- **Многоязычие.** На docs.eaeunion.org файлы на всех языках Союза, в API это поле `lang`. Индексировать только русский, следить за языком файла (случай с армянским DOCX).
- **Метаданные API.** В `eaeu_data.xsd` есть `status`, `date_of_entry_into_force`, `area_of_activity`, но в выгрузках они пустые. Связей «изменяет / изменён» в API нет. Статусы и граф изменений ведём сами, опора — карточки ТР на eec.eaeunion.org.

## 4. Выводы

**Единица ответа** — адресованный структурный элемент ТР или решения в редакции на дату. Два вида:
1. **Положение:** часть / пункт / подпункт статьи. Пример: «ТР ТС 021/2011, пункт 1 части 1 статьи 23». Нумерация — статья → часть → пункт → подпункт. Схема «1.4)» внутри «4. Схемы декларирования» — четыре уровня.
2. **Строка таблицы приложения:** показатель × допустимый уровень × группа продукции × условия и сноски. Адрес: «ТР ТС 021/2011, приложение 3, раздел 5, свинец — Мед».

Отдельные единицы:
- **строка перечня стандартов** (структурный элемент ТР → обозначение стандарта → примечание);
- **пункт изменяющего решения** — для вопросов «что изменилось».

**Поля сверх набора санитарного промта:**
- `edition_of` / `amended_by[]`: изменяющее решение, дата вступления, акт переходных положений, `transition_until`; история значения у строки таблицы (`previous_value`, `changed_on`);
- `consolidated_by_us: true` и признак сверки консолидации — для ЕАЭС официальной консолидированной редакции нет;
- `applies_to`: группа или вид продукции, исключения (непромышленное изготовление, общепит, ЛПХ), объект (продукция или процесс);
- `conformity`: форма (декларация / сертификат / госрегистрация / ВСЭ / регистрация объекта / госнадзор) и схемы — структурно, когда фрагмент о процедуре;
- `related`: применимые одновременно ТР (горизонтальные и вертикальные), перечень стандартов со строкой, ссылки на стандарты в семействе «стандарты»;
- `generic_ref`: родовая ссылка в тексте + во что разрешена и чем подтверждена (карточка ТР, перечень), либо «не разрешена»;
- ТН ВЭД — только из официальных перечней, как атрибут группы продукции, не как вывод базы;
- `lang` источника (русский текст официальный, файлы — на всех языках Союза).

**Специфично для ЕАЭС:**
- наднациональный уровень: два издателя-предшественника (КТС → ЕЭК), три органа (Совет, Коллегия, ВЕЭС);
- обязательная часть («ТР») и подзаконная связка (перечни стандартов, перечни продукции, переходные положения) живут разными решениями разных органов;
- горизонтальные и вертикальные ТР;
- оценка соответствия как центральная тема вопросов;
- граф связей не из текста.

**Общее с другими семействами:**
- адресация до пункта и строки таблицы;
- `lookup_norm` с условиями и сносками;
- консолидация из инструкций «изложить в редакции» (как у ведомственных актов, СП, ЦБ);
- реестр статусов, который ведём сами;
- родовые ссылки на «законодательство»;
- PDF-таблицы с поломанной вёрсткой.

Модель «строка таблицы = норма с conditions» из санитарного семейства переносится почти без изменений, только условием становится группа продукции.

**Границы:**
- база не относит конкретный товар к ТР или коду ТН ВЭД, не выбирает схему и не решает, переработанный ли продукт (мёд, полуфабрикат). Это идентификация (статья 6 ТР 021) — дело заявителя, ОС, таможни;
- база не решает, нарушение ли это и какая ответственность;
- база не говорит, действует ли конкретная декларация или свидетельство — это реестры (ФСА, единый реестр свидетельств). Реестры не нормативные документы; возможна будущая интеграция, пока вне базы.

Что база даёт: применимые ТР с основаниями, требование с адресом и редакцией на дату, переходные положения и связанные стандарты.
